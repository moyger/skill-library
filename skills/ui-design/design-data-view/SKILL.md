# Design a data view

Ask what decision the reader makes. Inspect the available fields, units, time range and missing values. Label sample figures when the design uses invented data.

1. Match the view to the question. Use a sorted bar chart for ranking, a line for change over time, a histogram for a distribution or a scatter plot for a relationship. Use a table when people need exact values or individual records.
2. Specify what position, length and colour mean, including the axis range, units and sort order. Start magnitude bars at zero. Use a meaningful centre for a diverging scale, such as zero change. Keep category meanings consistent across views.
3. Show how to recognise missing, stale and zero values. Leave a gap for missing observations where joining the points would imply measured continuity. Label the time covered and the last update when freshness affects the decision.
4. Make the same question answerable on a narrow screen and without hover. Direct labels, a text summary or a companion table can carry values that a legend or tooltip would otherwise hide.

Deliver the view or specification with its question, field mapping, example state and a check using the underlying records. For a queue with overdue work, for instance, a count can show the backlog while sorted rows tell the operator which item to open.
