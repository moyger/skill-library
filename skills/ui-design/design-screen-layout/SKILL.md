# Design a screen layout

Start with the intended user, their task, the target screen and representative content. Use the approved direction, existing components and spacing values where available. If the main task is unclear, ask what someone should be able to do here.

1. Write the reading order in plain words. On a service homepage it might be “Understand the service → check coverage → request a quote.” On a monitoring screen, an urgent status may deserve the strongest emphasis.
2. Place those items on a grid. Specify the content width, margins, columns and gaps for the available space. Explain what stacks first when the content stops fitting. Preserve the reading order when columns stack.
3. Put labels closer to their own values than to neighbouring groups. Align related items along a common edge. In a dense list, give each row a shared background or divider if spacing alone leaves ownership unclear. Remove redundant outlines where the edges are already implied.
4. Give elements with the same role a consistent appearance. Reserve the strongest difference in size, weight or colour for the item that needs attention. When a dialog is open, distinguish its boundary, title and actions from the page behind it.
5. Apply project text styles and colour roles. Walk through the main action using realistic copy and one relevant difficult state, such as a long address or an unavailable service. Record where someone could choose the wrong action even if the screen looks polished.

Deliver the requested frame, wireframe or written layout. For a written handoff, include the region order, sizing and spacing decisions, narrow-screen behaviour and one visible check for the main task.
